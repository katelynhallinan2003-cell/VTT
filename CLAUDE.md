# Working rules for this project

These are standing orders from the user (set 2026-11-22). Follow them without being asked.

## Ship straight to `main`

- When a piece of work is finished, **commit it and push it directly to `main` on `origin`.** No feature branches,
  no pull requests, no asking for permission first.
- Check before pushing: `npx tsc --noEmit` and `npx vitest run` must pass. Do not push broken work.
- One issue, one commit where practical, with `WIP.md` updated in the same commit.
- Never force-push. If the push is rejected (someone else pushed, branch protection, no access), stop and tell the user.
- Still ask first for anything destructive or hard to undo that the user did not ask for (rewriting history,
  deleting branches or data, touching the live Firebase project).

## Keep `WIP.md` up to date

`WIP.md` in the repo root is the list of every issue the user has given.

- **At the start of a session, read `WIP.md`.**
- **The moment the user gives an issue** (a bug, a feature, a change, including one that arrives while you are
  mid-task), add it to *Open* in `WIP.md` with the next number and today's date, then carry on. One entry per issue:
  if a message contains three issues, add three entries.
- Mark the one you are working on `(in progress)`.
- **When an issue is finished** (built, tested and pushed), move its entry to the bottom of the *Completed* list,
  tick it `[x]`, and add the completion date and a line on what shipped. Never delete entries.
- If the user says something still does not work, move it back to *Open* and note what is left.
- **Before every report to the user,** re-read their recent messages and check that every issue in them is in `WIP.md`.
- A plain question that needs no change to the project is not an issue and does not go in the file.

`TASKS.md` is the older ledger from before `WIP.md`. It is kept as history. Do not add to it.

## Project habits

- Stack: Vite + TypeScript + Preact + PixiJS 8, Firebase Realtime Database (rules generated by `npm run rules`), static hosting on GitHub Pages.
- Run it: `npm run dev`, then open `http://localhost:5173/?demo` (demo mode, no Firebase needed).
- Test: `npx tsc --noEmit`, `npx vitest run`, and the Playwright scripts in `tests/e2e/` (run against `npx vite preview`).
- Tell the user about database rule changes: `database.rules.json` has to be republished in the Firebase console by hand.
- End commit messages with the attribution lines required by the session.
