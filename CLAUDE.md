# Working rules for this project

## Keep `TASKS.md` up to date (always, without being asked)

`TASKS.md` is the ledger of everything the user has asked for. It is the standing way of working here:

- **At the start of a session, read `TASKS.md`.**
- **The moment the user asks for something** (including a message that arrives while you are mid-task), add it to
  *To do* in `TASKS.md` and keep going with what you were doing. Do not wait.
- Move items to *In progress* when you start them and to *Done* (with date and commit) when they are built, tested and pushed.
- If the user says something still does not work, move it back and note what is left.
- **Before every report to the user, audit:** re-read their recent messages one line at a time and compare with the
  ledger and the code. Anything missing goes into *To do*. After a conversation is compacted, re-read the summary the same way.
- Commit `TASKS.md` together with the code it describes.

## Project habits

- Stack: Vite + TypeScript + Preact + PixiJS 8, Firebase Realtime Database (rules generated by `npm run rules`), static hosting on GitHub Pages.
- Test: `npx tsc --noEmit`, `npx vitest run`, and the Playwright scripts in `tests/e2e/` (run against `npx vite preview`).
- Tell the user about database rule changes: they have to republish `database.rules.json` themselves.
- End commit messages with the attribution lines required by the session.
